# Лабораторная работа №3

Тема: создание базового каркаса приложения, Layered / Clean Architecture
и настройка окружения. Проект: Event Ticketing API (вариант 6).

## Что выполнено

1. Инициализировано приложение на Python и FastAPI.
2. Созданы каталоги `config`, `controller`, `service`, `domain`, `repository`.
3. Настроено чтение `.env` и переменных окружения с валидацией значений.
4. Реализован публичный `GET /api/v1/health`: `200 OK`, JSON с названием,
   версией, окружением и временем работы приложения.
5. Добавлены `.env.example`, `.gitignore`, инструкция запуска и проверки.
6. Контракт `openapi.yaml` дополнен health-check без авторизации.

## Что показать преподавателю

1. Структуру `app/` и создание зависимостей в `app/main.py`.
2. `.env.example` и `.gitignore`. Команда `git check-ignore .env` должна
   вывести `.env`, а `git ls-files -- .env` — ничего.
3. Запустить приложение по инструкции из `README.md`.
4. Открыть `http://127.0.0.1:8000/api/v1/health` в браузере или выполнить
   `curl.exe -i http://127.0.0.1:8000/api/v1/health` в другом терминале.
   Показать HTTP-статус, тип содержимого и поля JSON. Повторить запрос:
   `uptime` увеличивается.
5. Изменить `APP_NAME` или `HTTP_PORT` в `.env`, перезапустить приложение
   и показать, что конфигурация применяется.
6. Показать результат `python -m pytest -q` в виртуальном окружении и
   коммит лабораторной через `git log -1 --oneline`.

## Ответы на контрольные вопросы

### 1. Почему Service Layer не должен знать о деталях HTTP?

Сервис описывает сценарий приложения, например покупку билета. Контроллер
извлекает параметры HTTP, вызывает сервис и формирует ответ. Если сервис
не зависит от заголовков, JSON и FastAPI, его можно использовать из CLI,
фонового задания или другого транспорта и тестировать без HTTP-сервера.
В этом проекте `HealthService` возвращает обычную доменную модель.

### 2. Чем опасно хранение секретов в исходном коде?

Пароли и ключи могут попасть в удалённый репозиторий, его историю, копии
и логи. Удаление строки из последнего коммита не удаляет её из истории.
Конфигурацию передают через окружение, локальный `.env` не коммитят,
а `.env.example` содержит только безопасный шаблон. Если секрет уже утёк,
его нужно отозвать и заменить.

### 3. Зачем нужен `.env.example`, если `.env` находится в `.gitignore`?

Это шаблон необходимых настроек для другого разработчика и нового окружения.
По нему создают локальный `.env` и задают собственные значения. Так структура
конфигурации доступна в Git, а реальные секреты туда не попадают.

### 4. Для чего используется Health Check?

Он позволяет быстро проверить, запущено ли приложение и обрабатывает ли HTTP-запросы.
Его вызывают разработчики, системы мониторинга и средства оркестрации.
Текущий `/api/v1/health` проверяет работу процесса (liveness), возвращает
название, версию, окружение и время работы. Готовность обслуживать запросы
с зависимостями (readiness), например доступность БД, проверяют отдельно,
когда такие зависимости появятся.

### 5. Что такое Dependency Inversion и как она связывает слои?

Бизнес-логика должна зависеть от абстракции хранилища, а реализация работы
с БД — реализовывать эту абстракцию. Например, сервис покупки получает
интерфейс `TicketRepository`, а точка сборки передаёт реализацию для PostgreSQL.
Тогда БД можно заменить или подменить в тестах, не переписывая бизнес-правила.

В ЛР3 база данных ещё не используется. Точка сборки `app/main.py` уже
создаёт сервис и передаёт его контроллеру при сборке приложения.
Передача зависимостей (Dependency Injection) — способ связать объекты;
Dependency Inversion — принцип направления зависимостей между слоями.
Интерфейсы репозиториев появятся вместе с первыми сценариями работы с БД.
